- [x] SubTask 5.3: 实现阴影、发光、柔化边缘等图片与形状效果（性能不足时按档位降级为简化效果）
- [x] SubTask 5.4: 实现表格与图表（降级）的绘制
- [x] SubTask 5.5: 实现渲染输出格式与呈现方式：输出预乘 BGRA 位图，并支持编码为 WebP/PNG 供传输（编码方式依 Task 7 的通道结论定稿）
- [x] SubTask 5.6: 实现按缩放档位渲染（低档位用于缩略图，高档位用于主视图）与设备像素比适配
- [x] SubTask 5.7: 单元测试 + 视觉回归测试（对样本语料集渲染并与基准图做像素差异比对，设置允许阈值）
- 验证：`cargo test -p ppt-render` 通过（80 项单元 + 12 项 PPTX→位图端到端）；端到端测试用真实拼装的 PPTX 验证了渐变方向、椭圆填充与描边、组合内子形状的烘焙变换、主题 accent1 文字色、确定性、多分辨率内容占比一致、缓存复用、多线程渲染；实测单页 720×540 渲染 < 80ms
- 说明：
  - SubTask 5.5 的输出格式定稿为**预乘 RGBA8**（`PixelFormat::Rgba8Premultiplied`）而非 BGRA —— 这是 tiny-skia 的原生格式，省掉一次全图遍历；编码为 PNG 时由编码器还原直通 alpha
  - SubTask 5.7 的「视觉回归」以「像素级断言（渐变方向、颜色命中数、内容占比与分辨率无关）」实现，未引入外部基准图；接入真实课件语料集后再补差异比对阈值
  - 图片填充未走 tiny-skia 的 `Pattern` 着色器（它借用位图，与 `Paint<'static>` 生命周期冲突），改为「形状路径建遮罩 + 透过遮罩绘制位图」
  - 阴影以「多层递减透明度的偏移填充」近似（tiny-skia 无内置模糊滤镜），对课件常见的浅阴影足够且不分配大缓冲

## Task 38: 渲染管线的性能真相 —— 已交付

## Task 40: 动画逐元素弹出 —— 让办公软件**按步出图** —— 已交付

老师一句话点破了 Task 39 的漏洞：
**「无法逐页弹出：弹出的都是已经显示的内容」**。

根因是架构性的：`Slide.Export` 出的是一张**拍平的整页图**，上面什么都有，
包括这一步还不该露面的答案。管线里 `render_direct` 拿到 `PlayState`
压根不看它 —— 于是每一步拿到的都是同一张「全播完」的图。

三条底线里，「按钮能点、视频能播」靠双源架构解决了，
**「元素按 ppt 逐一弹出」必须让办公软件自己画每一帧**。

### 怎么让 WPS 画「第 k 步的样子」

- [x] 实测确认（PowerShell 直调 COM）：
  **`Shape.Visible = msoFalse` 会被 `Slide.Export` 尊重** ——
  同一页导出两次，1,020,534 字节 vs 1,217,773 字节；还原后字节数完全一致
- [x] `Shape.Id` 就是 OOXML 的 `p:cNvPr/@id`，与解析器里的 `shape_id` **同值**，
  所以「哪一步该藏谁」可以两端直接对上
- [x] 每一步导出时把「这一步还不该出现」的形状隐掉，存成
  `<页码>.<已播步数>.png`；`<页码>.png` 仍是全部播完的样子
- [x] 逐元素弹出现场验证（真实课件第 1 页，4 步）：
  `0.0.png` 只有背景图 → `0.1.png` 出现圆角矩形 → `0.2.png` 出现装饰图
  → `0.3.png` → `0.png` 文字最后到位

### 算账人与出图方分工

「哪一步该藏谁」需要 OOXML 解析器，而「让办公软件画」在另一条线程上。

- [x] `ppt-convert` 只接受一份**现成的清单**：`StepPlanner`
  （`Arc<dyn Fn(usize) -> Vec<Vec<u32>>>`），它不认识 OOXML
- [x] 清单由 `ppt-app` 的 `step_hide_plans` 算出，规则**复用 `Build::visible_in`**
  —— 自研渲染内核走的也是它，两边不会各说各话
- [x] 出图方（写）与显示层（读）**共用同一个 planner**
  ⇒ 步数必然一致，帧不会错位
- [x] 解析只发生在「翻到动画那一步」或「后台出到那一页」，
  **不在打开课件那条路上**（首屏预算守住了）

### 三个踩过的坑

- [x] **`MsoTriState` 读回来是 `VT_I4` 不是 `VT_BOOL`**
  - 症状：194 张分帧全部与整页图**字节完全相同**，日志里一句错都没有
  - 根因：`as_bool` 只认 `VT_BOOL` → 每个形状都被当成「不可见」→ 谁都没藏
  - 修法：`VT_BOOL` 与 `VT_I4` 都认
  - 教训：**「什么都没发生」也是一种失败信号**，不能只看有没有报错
- [x] **老缓存会让出图任务一次都不启动**（症状：一直转圈）
  - 整页图全在了 ≠ 分帧也在了；`ready < pages` 判断漏掉了后半句
  - 修法：出图任务在分帧全部成功后写下 `steps.done` 标记，
    打开时「整页图不全 **或** 没有这个标记」才排任务（已出好的各自跳过）
- [x] **「还在排完」标志的默认值必须是「已排完」**
  - 默认 `false` ⇒ 没有任务在跑时显示层永远等下去（一直转圈）
  - 只有 `begin_warm`（任务真的开跑）有资格清零

### 已知限制（写在这里，免得下次当成 bug 查）

- 强调动画（变色、放大）**没法用静态帧表示** —— 它不改变可见性，
  办公软件导出的是「未被强调」的样子。这类步仍由自研渲染内核合成，
  误差为近似（见 Task 24）。
- 一页 N 步会多出 N 张整页 PNG（本课件 194 张 ≈ 180MB）。
  分帧只在含动画的页、且只会出一次；**缓存淘汰尚未实现**。

老师三条反馈，第一条是 Task 40 漏掉的，后两条是新问题。

### 一、「全部显示所有页面元素后再一个一个往上面砸」

- 根因：**段落级动画**（`p:txEl`，「项目符号逐条弹出」，课件里最常见的形态）

  - 实测 WPS 的 `Font` 上既没有 `Visible` 也没有 `Hidden`（两个都不存在）
  - `TextRange2.Paragraphs(i).Font.Fill.Transparency = 1` 有效：

### 二、「元素和翻页反应有点慢」

量出来的数据（改之前）：

| 操作 | 后端耗时 | 载荷 |
|---|---|---|
| 全屏整页渲染 | 62~147ms | **7.9MB** |
| 缩略图（173×97） | 263~**2193ms** | 0.1MB |

两处根因：

- [x] **后端 3 秒忙等把工作线程占满**（最大的那个）
  - 缩略图一露出来十来个请求同时发，每个都在后端死等最多 3 秒；
    老师接着翻页的那次请求只能排在它们后面 —— 手感就是「反应慢」
  - 修法①：后端死等 3000ms → **250ms**（只 absorb 一次很快的出图），
    剩下的等待交给前端轮询（**轮询不占后端线程**），间隔 150ms
  - 修法②：缩略图请求**限流到 2 个并发**，它们永远不许抢老师的操作
- [x] **传了 7.9MB 原始像素**，而那张图本来就躺在磁盘上
  - 走「读 → 解码 → 缩放 → 转预乘 → 传原始像素」，每一步都是白花的
  - 修法：`DocumentSource::raster_png_path` + `render_page` 快路 ——
    **把 PNG 文件原样传给前端**，解码与缩放交给浏览器（有 GPU）
  - 代价：写进 `decodeFrame` 的一条嗅探（PNG 固定以 `89 50 4E 47` 开头，
    原始帧的头 4 字节是宽，撞不上）
  - 缩略图不走快路（`wants_native_raster`）：那等于把整页图塞进 173×97
    的格子，39 张能吃掉几百 MB 内存

**结果：日志里「渲染偏慢」（>60ms）从每页都有变成 0 条。**

### 三、「有时会黑屏（全屏播放时）」

黑屏不是一个 bug，是一类「画布被清空了却没人再画」的故障。堵住三个口子：

- [x] **`animateFor` 的 Promise 可能永远不 settle**
  - 老师手快时，上一步动画还没演完就点下一步/翻页；旧动画要画的那张位图
    可能刚被新的一次绘制 `close()` 掉，`drawImage` 抛异常后 Promise 永不
    settle → 调用方的 `finally` 永不执行 → 画布停在「已清空、未画出」
  - 修法：动画改为**可中止**（`paintSeq` 令牌，谁后开始谁负责画），
    且 `draw` 抛异常时一律 resolve
- [x] **`paintFrame` 会拿一张已关闭的位图去画** —— 它的宽高是 0，
  于是画布被清成 0×0，之后怎么翻都是黑的。现在直接跳过
- [x] **`#fade` 黑场遮罩可能留在屏幕上**（全屏切换时用的那层）
  - 中途任何一步抛异常都会让它留在屏幕上，而 `state.presenting` 已经是
    true，再按 F5 也会被「已经在放映」挡回来 —— 彻底卡在黑屏
  - 修法：`try/finally`，**无条件收掉**

> **教训（又一次）：「什么都没发生」也是一种失败信号。**
> 段落隐藏第一版静默失败的原因是：`Paragraphs(i)` 是**带参数的属性**，
> 必须用 `DISPATCH_PROPERTYGET` 调，我用 `DISPATCH_METHOD` 调，
> 被拒之后调用点 `else { continue }` 一路静默 —— 分帧生成成功、
> 日志一句错都没有、帧的内容却和整页图一模一样。
> 现在这类「一段都没藏成」会明确报警。

## Task 42: 缓存淘汰误删画面来源 + 旧版 .ppt 自动转换 —— 已交付

### 一、「有的时候会出现显示旧版自研渲染的 ppt」

- **根因在缓存淘汰，不在渲染链路。**
  `DiskCache::enforce_budget` 从 **`root`** 递归收集文件、按修改时间删最旧的，
  上限 512MB —— 而 `root` 就是 `%LOCALAPPDATA%\OpenPPTView\cache`，
  **「办公软件出的逐页 PNG」也住在同一个 root 下**（`cache/wps/…`）。
  于是它把**画面来源当成缓存副产物删掉了**，那几页只能退回自研渲染内核。
- 实测证据：某课件第 0~10 页的整页图与 0~9 的分帧一起消失、第 11 页往后完好
  —— 正是「按 mtime 由旧到新删」的形状。

## Task 44: 「升级完了，双击课件起来的还是老版本」 —— 已交付

老师升级到最新版、退出，再双击一个 `.pptx` —— 起来的却是旧版本。

### 一、根因：关联是**分档**写的，而 HKCR 里 HKCU 优先

- ProgID 跟着安装方式走：按机器装（`C:\Program Files`）写 HKLM，
  按用户装（`%LOCALAPPDATA%\Programs\OpenPPTView`）写 HKCU。
- 这台机器上先后装过这两种：早先按用户装的那份把
  `HKCU\Software\Classes\OpenPPTView.pptx\shell\open\command`
  指向了它自己；后来按机器升级写的是 HKLM。
  **HKCR 的解析顺序是 HKCU 优先**，于是那条影子一直压着新的。
- 界面上完全看不出来：`FileExts\.pptx\UserChoice` = `OpenPPTView.pptx`，
  「默认打开方式」显示的确实就是 OpenPPTView。
- 实测（修复前）：`HKCR\OpenPPTView.pptx\shell\open\command` =
  `"C:\Users\65411\AppData\Local\Programs\OpenPPTView\OpenPPTView.exe" "%1"`
  —— 那是 9/20 22:33 装下的旧副本，文件还在磁盘上。
  同一时刻 `.pdf` 已经指向 Program Files（那份是应用自己登记的），
  所以只有 `.pptx` 有问题 —— 这个不一致本身就是「两个来源在写同一个键」的证据。

### 二、修法

- [x] `associations::status` 的「已注册」以前只看 ProgID 键在不在，
  现在还要看它的命令**指着谁**（新增 `points_here`）。键在、但指着另一个副本，
  就不算「能打开」，界面也不该说「已经是默认了」。
- [x] `repair_if_dangling` → `repair_if_needed`：把「指着另一个副本」也纳入自愈。
  但**只有装在这台机器上的那一份**才有资格改（`may_repoint` 用
  `InstallLocation` 判断）—— 否则开发时直接跑 `target\release\ppt-app.exe`
  也会把老师的 `.pptx` 抢过去，又造出一次「打开的是另一个版本」。
- [x] 安装器装完顺手 `settle_legacy_user_install`：发现有按用户装过的旧副本
  （且不是这次装的地方）就收掉它 —— 先 `--quit` 请它退出、删目录、清掉它
  写在 HKCU 的卸载登记与偏好 —— 再把 HKCU 里那几条指向它的命令改指到新位置。
  这样「双击课件 → 起来的一定是这一份」不再依赖老师先手动跑一次新版。
- [x] 设置页 / 欢迎页跟着诚实：`pointsHere` 为假时如实显示
  「注册指向的是另一个副本，点『注册到本应用』改过来」。

### 三、顺手修掉的第二个问题：装完拉起来的那份是**管理员权限**

安装程序是提权的，`ShellExecuteW` 拉起的子进程继承管理员权限。实测两条后果：

- 从资源管理器往窗口里拖课件会被 UIPI 挡掉（普通权限进程不能往高权限窗口拖放）；
- **双击课件时新起的普通权限实例，没法把文件转交给那个常驻的高权限实例**
  （消息同样被 UIPI 挡掉）—— 老师看到的是「双击了，什么都没发生」。
  实测：普通权限的 `--quit` 叫不动管理员权限的那个实例，提权的可以。

修法：`launch_app` 改成**请资源管理器代启动**（它自己是普通权限，由它拉起
就是普通权限 —— 安装程序里最常见的换 token 办法，不必自己去复制外壳令牌），
起来之后用 `process_running` 确认；没起来再退回直接启动。

## Task 45: 触摸屏拖不动悬浮球 —— 已交付

### 一、现象与根因

放映时收起的那条胶囊（「悬浮球」）按住就能拖（见 `bindPresentBarDrag`）——
鼠标可以，**触摸屏上不行**：手指一按一拖，它只挪十几像素就停住。

- 根因是 `touch-action` 的**生效值**。它本身不是继承属性，但按规范会与
  祖先链上的取值**取交集**；而这条胶囊不在 `#stage` 里（它在 body 下、
  `position: fixed`），于是拿到的是 `body` 的 `manipulation` ——
  那一条允许浏览器接管平移手势。
- 手指拖动时浏览器认定「这人在滚页面」，立刻发 `pointercancel` 掐断指针序列：
  我们的拖动只走到第 2 个 `pointermove`，而且**收不到 `pointerup`**。
  鼠标不存在「被浏览器接管」这回事，所以这个毛病只在触摸屏上出现。
- 实测（CDP 往页面注入真实触摸事件；这台开发机没有触摸屏，但注入走的是
  浏览器同一条输入管线，手势识别与 `pointercancel` 都会真的发生）：
  `down 1, move 2, cancel 1, up 0`，横向只挪了 24px。

### 二、修法

- [x] `#present-bar` 加 `touch-action: none`（与 `#stage`、`#ink-layer` 取值一致：
  放映时手势归脚本）。光在元素自己身上写不够 —— 关键是这条属性与 `body`
  那条取交集之后的结果。

### 三、验证

| 场景 | touch-action（生效） | pointer 事件 | 位移 | 结论 |

| 修复前 | `auto`（∩ body 的 manipulation） | down 1, move 2, **cancel 1**, up 0 | 24px | 被浏览器掐断 |

## Task 46: 黑板 + 按钮笔 + 删掉黑屏 + 放映条视觉 —— 已交付

### 一、黑板（新增）

原来放映条上那颗是「黑屏」—— 把屏幕压黑，讲课中间想临时板书只能干看着一块黑。
现在换成**黑板**：点一下，一块深墨绿的板子盖住课件，笔迹落在上面，再点一下回到课件。

- 板子与标注层**完全重合**（`layoutCanvases` 把它们放进同一组摆位），所以
  「看得见的板子」就是「写得上去的范围」—— 不会写到边上没有落笔点。
- **板书是多页的**（这条是老师后来明确的）：在黑板上按翻页键翻的是**板书自己**的页
  （页码牌显示「板书 2」），翻到最后再按就新开一页，最多 20 页。
  翻页**不会**退出黑板 —— 连着按几下显然是「再给我一页写」，不是「放我回课件」；
  下板按黑板按钮或 Esc。要跳课件页（缩略图、输页码、Home/End）才下板。
- 板书自己占一套格子（`board1`、`board2`…，见 `inkKey`）：撤销、重做、清空、橡皮、
  粗细颜色**全部照旧可用** —— 那些代码本来就按 `inkKey()` 取笔迹，不必给黑板另写一套。
- 上板顺手换笔色：面板是深墨绿，老师要是正拿着黑色笔上去就是「写了个寂寞」。
  上板时把暗色（相对亮度 < 0.45）临时换成白粉笔色，下板还回去。

### 二、板书自动保存（跟课件走）

- 板书和课件标注存在**同一份旁挂文件**里（`<课件>.oppv-annot.json`，就在课件旁边）。
  后端把标注当不透明 JSON 字符串收发，所以多出一批 `boardN` 键**不用改 Rust**。
- **停笔 3 秒自动落盘**（`scheduleAutoSave`，去抖）：老师在上课，不能指望他记得按
  Ctrl+S，板书更是随手写的。落盘走 `quiet`，不弹「已保存」打断讲课。
- 换课件前先补存一次：自动保存是去抖的，而老师完全可能写完最后一笔就点开下一份课件
  （此刻后端手上还是旧课件，所以这次保存写在它自己旁边）。
- 实测：上板写两页板书 → 停笔 4 秒 → 文件里出现 `board1`/`board2` 两笔（笔色 `#ffffff`）；
  重新打开同一份课件 → 两页板书都读回来，上板即可见。

### 三、按钮笔（适配）

- 这类笔在系统看来就是个键盘，而**不同牌子发的键不一样**。以前只认
  `PageDown/PageUp/←/→/空格`，而「播放」键发回车或媒体键的笔（很常见）按下去没反应。
  现在 `NEXT_KEYS`/`PREV_KEYS` 把常见发键全收下：翻页键、方向键、空格、回车、
  `MediaTrackNext/Previous/PlayPause`。
- 修掉一个会让老师以为「笔坏了」的坑：页码输入框拿到焦点后，翻页键会被输入框吃掉。
  现在翻页键**放行**（先失焦再翻页），输入框里回车仍然按「跳到那一页」处理。
- 便宜的笔按住不放会连发几十个 keydown，一路翻到底。加了 130ms 节流：
  有意快速点（≥150ms）不受影响，连发被拦。
- 笔上那颗「黑屏」键大多发 `B`：现在打开的是黑板（能写），不是黑幕。
- 设置页「您用什么操作」补了一句说明。

### 四、删掉黑屏

`#overlay`（含 `.black`/`.white`）、`setBlack`、`p-black`/`t-black`、右键菜单里的
「黑屏」项、Esc 多级退出里那一条，全部删掉 —— 功能被黑板取代，留着只会两套并存。

### 五、UI

- `#present-bar` 上的分隔线与色环原本用浅色主题的 `--border-strong`

  `rgba(255,255,255,0.18)`。
- 黑板按钮**留在收起态**的胶囊里：它是开/关式的，藏起来就变成「上得去、下不来」，
  只能先展开工具条。
