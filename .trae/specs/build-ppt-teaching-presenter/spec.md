# 极速课件讲演器（OpenPPTView）Spec

## Why

学校教室/机房的讲课电脑普遍是老机器（4GB 内存、机械硬盘、双核 CPU），WPS 与 PowerPoint 冷启动动辄十几秒、占用内存高、翻页还要等；并且它们是为「编辑」设计的，不是为「讲课」设计的——老师站在触控一体机前想随手圈画、遮挡、聚焦，操作路径都很绕。

本项目要做一个**只做讲课这一件事**的桌面讲演器：双击即开、翻页即显、抬手就能写，并在触控屏上做到真正跟手。

## What Changes

- 新建桌面应用 **OpenPPTView**（工作区当前为空仓库）。
- 技术栈：**Tauri 2（Rust 核心 + 系统 WebView2 外壳）**。
  - 依据：目标系统为 Windows 10 1709+，该版本起系统自带 WebView2，无需额外运行时；相比 Electron 省去整包 Chromium，安装体积与常驻内存显著更低。
  - **注意**：WebView2 对 Windows 7/8.1 的支持已于 2023-01 随 Edge 109 终止，因此本项目的「老电脑」下限是 Windows 10 1709。若将来必须支持 Win7，需更换为原生 Direct2D/GDI 渲染路径（本规格不含）。
- **幻灯片渲染不走 WebView 的 DOM 排版**，而是由 Rust 侧自研 OOXML 渲染内核直接光栅化为位图，WebView 只负责 UI 外壳与标注画布。这是与「网页套壳 PPT 预览器」的本质区别，也是速度来源。
- 新增触控/手写笔优先的标注系统。
- 新增面向讲课场景的讲演模式（双屏、备注、计时、黑屏/幕布/聚光灯/放大镜/激光笔）。
- 格式支持分阶段交付：**本规格实现 .pptx 与 .pdf**；.docx 与 .ppt（97-2003 二进制）列入后续阶段，不在本轮任务范围内。

### 明确不做（本轮）

- 不做幻灯片编辑、不做 PPTX 导出、不做协作/云同步。
- 不做 .docx、.ppt、.xlsx 渲染（列入后续阶段 Requirements，但不进入本轮 tasks）。
- 不做动画与转场的时间轴播放（首版按「最终状态」静态呈现；`.pptx` 中带 `p:timing` 的页面按末帧渲染）。
- 不做宏/VBA、不做内容编辑，完全离线、不联网、不上传任何文件。

## Impact

- **Affected specs**：全新能力域，无既有规格需要修改。
- **Affected code**：`d:\code\OpenPPTView` 全量新建。规划为 Rust workspace：
  - `crates/ppt-core`：OPC/ZIP 随机访问、OOXML 解析、SceneGraph 中间表示
  - `crates/ppt-text`：字体解析、整形、CJK 断行、文本布局
  - `crates/ppt-render`：SceneGraph → 光栅位图
  - `crates/ppt-pipeline`：缓存、预渲染调度、脏区/取消
  - `crates/ppt-format-pptx` / `crates/ppt-format-pdf`：各格式 → SceneGraph 适配
  - `crates/ppt-app`：Tauri 应用、命令、自定义协议、文件关联
  - `web/`：前端外壳（阅读器 UI、标注画布、讲演控制台）
- **关键第三方依赖（均需为纯 Rust 或零 C 依赖，以适配老机器并保持体积）**：
  - `zip`（按需解压）、`memmap2`（内存映射）、`quick-xml`（流式 XML）
  - `fontdb` + `ttf-parser` + `rustybuzz`（字体解析与整形）、`unicode-linebreak`（CJK 断行）
  - `tiny-skia`（CPU 光栅化）、`image`（位图解码）
  - `rayon`（并行渲染）、`lru`（缓存）
  - PDF：`hayro`（纯 Rust CPU 光栅器）为主选，`zpdf-render`（tiny-skia CPU / wgpu GPU 双后端）为备选，需经选型验证后定稿
  - 后续阶段：`cfb`（MS-CFB 容器，读旧版 .ppt 用）

## 性能预算（验收基准，硬指标）

以 Windows 10 / 4GB RAM / 机械硬盘 / 双核 CPU 的教室老机为基准环境，与「同一台机器上的 WPS 演示」对比：

| 指标 | 预算 |
| --- | --- |
| 进程启动 → 窗口可见 | ≤ 400ms |
| 打开 100 页 pptx → 第 1 页可交互 | ≤ 1.2s |
| 翻到已预热页 | ≤ 16ms（不掉帧） |
| 翻到未预热页 | ≤ 120ms，且期间保留上一帧、无白屏 |
| 打开 100 页含图 pptx 的常驻内存 | ≤ 350MB |
| 打开 100 页 pptx 的总磁盘读放大 | ≤ 文件大小的 1.3 倍 |
| 触屏笔迹跟手延迟 | ≤ 30ms（从指针事件到屏幕像素） |
| 安装包体积 | ≤ 25MB（不含可选离线 WebView2 包） |

## ADDED Requirements

### Requirement: 启动与首屏时延

系统 SHALL 在基准环境下满足上表「进程启动 → 窗口可见 ≤ 400ms」「打开 100 页 pptx → 第 1 页可交互 ≤ 1.2s」的预算，且启动过程中不显示 splash 窗口。

#### Scenario: 双击图标冷启动
- **WHEN** 用户在冷启动状态下双击桌面图标
- **THEN** 400ms 内出现可辨认的应用窗口骨架（侧栏与工具条轮廓），未出现空白页或阻塞式加载动画
- **AND** 1.2s 内第 1 张幻灯片完整呈现且可响应翻页与标注输入

#### Scenario: 双击课件文件直接打开
- **WHEN** 用户在资源管理器中双击一个 100 页的 `.pptx`
- **THEN** 应用直接进入该课件的第 1 页，不经过起始页或欢迎页

### Requirement: 幻灯片级惰性解析

系统 SHALL 不整体解析演示文稿，仅解析当前页及其相邻页；未访问的幻灯片不进入内存。

#### Scenario: 打开 100 页课件
- **WHEN** 打开一个 100 页 pptx
- **THEN** 首屏只完成第 1 页的解析与渲染，并在后台预热第 2 页
- **AND** 打开阶段不触发对第 3 页及之后幻灯片 XML 的解压与解析

#### Scenario: 大媒体文件不被读取
- **WHEN** 打开的 pptx 中 95% 体积集中在少数几页的大型嵌入视频/图片
- **THEN** 打开阶段的总磁盘读取量不超过课件体积的 30%，且不读取未被渲染页所引用的媒体流

### Requirement: 幻灯片缓存与预渲染调度

系统 SHALL 提供两级缓存（内存 LRU + 磁盘缓存）与带优先级的预渲染队列，并支持在快速翻页时取消已过期的渲染任务。

#### Scenario: 顺序翻页
- **WHEN** 老师连续按空格向后翻页
- **THEN** 每次翻页在预算内呈现，且在翻页过程中已排队的过期渲染任务被取消，不阻塞当前页

#### Scenario: 回头看已讲过的页
- **WHEN** 老师回翻到之前访问过的幻灯片
- **THEN** 该页从缓存中命中并即刻呈现

#### Scenario: 磁盘缓存
- **WHEN** 同一个课件第二次打开
- **THEN** 首屏时延不劣于首次打开，且缩略图与已渲染页可直接命中磁盘缓存

### Requirement: 帧呈现策略

系统 SHALL 在新一帧就绪前保留上一帧画面（双缓冲），任何情况下不出现白屏或半渲染画面。

#### Scenario: 翻到未预热页
- **WHEN** 跳转到一页尚未预渲染的幻灯片（如用缩略图跳到第 87 页）
- **THEN** 画面持续显示原幻灯片直至新页就绪，就绪后一次性切换，切换过程带短促淡入过渡且不阻塞输入

### Requirement: PPTX 渲染保真度

系统 SHALL 正确渲染 `.pptx` 的以下元素：主题/母版/版式三级继承（颜色、字体、占位符位置）；纯色/渐变/图案/图片填充；形状轮廓（宽度、虚线、端点、连接方式）、圆角与自定义几何路径；直线、曲线、自由曲线；组合形状与嵌套变换；文本框（自动换行、内边距、横竖排、垂直对齐、项目符号与编号、自动缩放）；表格（含合并单元格、边框、底纹）；图片（裁剪、旋转、翻转、本地/链接）；图片效果（阴影、发光、柔化边缘）；超链接与动作按钮；页码/日期/页脚占位符；演讲者备注。

#### Scenario: 常见教学课件
- **WHEN** 打开由 PowerPoint/Keynote/WPS 导出的常规教学课件
- **THEN** 版式、配色、字体层级、图片位置与课件在 WPS 中的呈现基本一致（主观评审通过、无素材丢失）
- **NOTE** 对 SmartArt、图表等复杂对象，首版允许降级为「静态化呈现 + 保留可读文本」，但不得出现空白或报错

#### Scenario: 缺失字体
- **WHEN** 课件使用了本机未安装的字体
- **THEN** 系统按字体回退链选择替代字体，中文优先回退到系统 CJK 字体，且不出现豆腐块或文字裁切

#### Scenario: 竖排与中英混排
- **WHEN** 幻灯片中包含中文、英文、数字、标点混排的段落
- **THEN** 断行符合中文排版习惯（不在行首出现闭标点、行尾不对齐开标点/数字断开），行高与段落间距与课件设定一致

### Requirement: 输入统一抽象（触屏 / 手写笔 / 鼠标）

系统 SHALL 使用 Pointer Events 统一处理触摸屏、手写笔与鼠标输入，并显式区分输入源类型（`pointerType`）。

#### Scenario: 三端一致
- **WHEN** 老师分别用鼠标、手写笔、手指在触控一体机上操作
- **THEN** 三种输入都能完成翻页、标注、缩放、工具栏点击，无需要各自不同的操作路径

### Requirement: 触屏与手写笔深度适配

系统 SHALL 针对触控讲课一体机做专项适配，包含以下能力：手写笔压感映射线宽；采集高频合并采样点（`getCoalescedEvents`）并做贝塞尔平滑以获得笔锋；手掌误触抑制；单指绘制与双指缩放/平移的手势分离；坐标按画布缩放与设备像素比正确映射；笔迹绘制在独立标注层并按脏矩形局部重绘。

#### Scenario: 手写笔板书
- **WHEN** 老师用手写笔在触控屏上书写
- **THEN** 笔迹跟手延迟 ≤ 30ms；用力时线条变粗、轻触时线条变细；笔迹平滑无折线感

#### Scenario: 手掌误触抑制
- **WHEN** 老师书写时手掌贴在屏幕上，且手写笔处于活跃状态
- **THEN** 手掌接触不产生任何笔迹，也不触发平移/缩放

#### Scenario: 双指缩放不误写
- **WHEN** 老师双指捏合缩放幻灯片
- **THEN** 画布按手指中心缩放，且全程不产生任何笔迹

#### Scenario: 触摸目标尺寸
- **WHEN** 老师在触控屏上点击工具栏按钮
- **THEN** 所有可点击控件的触摸热区不小于 44×44 逻辑像素，且相邻控件间距足以避免误触

### Requirement: 标注工具套件

系统 SHALL 提供完整的标注工具：画笔（≥6 种预设颜色 + 自定义取色）、粗细调节（≥4 档预设 + 连续调节）、荧光笔（半透明且绘制在内容之下）、橡皮擦（逐笔擦除与区域擦除两种模式）、撤销与重做（≥50 步）、清空当前页；标注 SHALL 以「幻灯片索引」为键绑定，在同一会话内翻页往返时保持不丢失。

#### Scenario: 圈画重点后继续讲课
- **WHEN** 老师在第 3 页画了圈注，翻到第 5 页又翻回第 3 页
- **THEN** 之前画的圈注原样保留，且不随窗口缩放而错位

#### Scenario: 误操作撤销
- **WHEN** 老师连续画了多笔后按 Ctrl+Z
- **THEN** 按笔迹粒度逐笔撤销，重做（Ctrl+Y）可恢复

#### Scenario: 退出提示
- **WHEN** 课件存在未保存的标注且老师关闭窗口
- **THEN** 系统询问「保存标注 / 不保存 / 取消」，选择保存后标注以旁挂文件形式随课件存放（不修改原课件）

### Requirement: 讲演模式

系统 SHALL 提供讲演模式，包含：全屏放映；多显示器选择（可指定在某块显示器上全屏）；缩略图导航侧栏；跳页；黑屏/白屏；幕布遮挡（自上而下/自下而上/左右遮罩）；聚光灯；放大镜；激光笔；讲稿备注面板；讲演计时器；快捷键自定义。

#### Scenario: 双屏授课
- **WHEN** 老师笔记本外接投影仪，长按「放映」并选择在显示器 2 全屏
- **THEN** 投影仪全屏显示幻灯片、无任何工具条或鼠标指针残留；笔记本屏幕显示控制台（当前页缩略图、下一页预览、讲稿备注、计时器、放映进度）

#### Scenario: 单屏授课快捷操作
- **WHEN** 老师在单屏授课中按下放映快捷键
- **THEN** 可使用预设快捷键完成：翻页、跳页、黑屏/白屏、幕布、聚光灯、放大镜、激光笔、唤出/隐藏工具栏、切换画笔与橡皮

#### Scenario: 临时挡住内容提问
- **WHEN** 老师按幕布快捷键
- **THEN** 画面被幕布自下而上遮挡，再次按下时反向收回，遮挡过程为流畅动画且不卡顿

#### Scenario: 讲稿备注与计时
- **WHEN** 老师进入讲演模式
- **THEN** 计时器开始计时，控制台侧显示当前页的演讲者备注；暂停讲演时计时暂停

### Requirement: 幻灯片导航与阅读体验

系统 SHALL 在窗口模式下提供缩略图侧栏、页码跳转、缩放（50%–400%）、适应窗口、适应宽度、滚轮翻页、空格/方向键翻页、拖动平移、键盘快捷键（含全屏 F5）。

#### Scenario: 快速定位
- **WHEN** 老师输入页码 42 并跳转
- **THEN** 直接定位到第 42 页，且缩略图侧栏同步滚动到对应位置

#### Scenario: 缩放后标注对齐
- **WHEN** 老师将页面放大到 200% 后在某一位置标注，再缩回 100%
- **THEN** 标注始终锚定在幻灯片的同一相对位置

### Requirement: 文件打开与关联

系统 SHALL 支持：注册 `.pptx`（及本规格支持的其它格式）文件关联；从资源管理器双击打开；拖拽文件到窗口打开；命令行参数打开；最近打开列表；同一应用内多标签或多窗口打开。

#### Scenario: 拖拽打开
- **WHEN** 老师把课件从 U 盘拖进窗口
- **THEN** 文件被打开，且 U 盘拔出后已缓存的页面仍可正常浏览

#### Scenario: 损坏文件容错
- **WHEN** 打开一个部分损坏或类型不符的文件
- **THEN** 系统给出明确的中文错误提示（指出问题页或问题部件），不崩溃、不静默白屏

### Requirement: PDF 支持

系统 SHALL 支持打开 `.pdf` 并复用同一套渲染调度、缓存、标注与讲演能力。

#### Scenario: 打开 PDF 课件
- **WHEN** 老师打开一个 200 页的 PDF
- **THEN** 同样满足首屏时延、惰性渲染与翻页预算，且可在 PDF 上正常标注与放映

### Requirement: 性能档位自适应

系统 SHALL 在启动时探测 CPU 核心数、可用内存与图形能力，自动选择渲染与调度档位（如预渲染页数、光栅线程数、是否启用 GPU 光栅），并允许用户在设置中手动覆盖。

#### Scenario: 低配机器自动降级
- **WHEN** 应用运行在 4GB 内存、双核 CPU 且无独立显卡的机器上
- **THEN** 自动降低预渲染页数与缓存上界，优先保证当前页响应与不卡顿，且界面不出现「性能不足」的打扰性提示

#### Scenario: 手动覆盖
- **WHEN** 老师认为翻页不够快、在设置中调高预渲染页数
- **THEN** 设置立即生效并在下次打开课件时使用

### Requirement: 离线与隐私

系统 SHALL 完全离线运行：不发起任何网络请求、不上传课件与标注内容、不内置遥测与崩溃上报。唯一允许的网络行为是用户显式触发的 WebView2 运行时安装。

#### Scenario: 断网环境
- **WHEN** 在完全断网的教室电脑上使用
- **THEN** 全部功能可用，无任何功能因网络不可用而降级或报错

### Requirement: 安装与部署

系统 SHALL 提供 Windows 安装包，包含：NSIS 安装程序；系统未安装 WebView2 时的引导安装（支持离线包作为可选组件）；文件关联注册；静默安装参数；卸载后不残留缓存与注册表项。安装包体积 SHALL ≤ 25MB。

#### Scenario: 机房批量部署
- **WHEN** 管理员以静默参数在多台机器上安装
- **THEN** 安装过程无需人工交互，安装完成后双击 `.pptx` 可直接由本应用打开

## 后续阶段 Requirements（本规格记录、不在本轮实现）

### Requirement: DOCX 支持（第二阶段）

系统 SHALL 支持打开 `.docx` 并按页面阅读、标注与放映，需实现流式文档排版（段落、分页、表格、图片、页眉页脚、多栏）。

### Requirement: 旧版 PPT 支持（第三阶段）

系统 SHALL 支持打开 PowerPoint 97-2003 二进制 `.ppt`，需实现 MS-CFB 复合文档容器解析、MS-PPT 记录流解析与 MS-ODRAW（Escher）绘图对象解析，并映射到同一 SceneGraph。

### Requirement: 动画与转场（第三阶段）

系统 SHALL 支持播放 `.pptx` 中定义的进入/强调/退出动画与幻灯片转场，并支持「跳过动画直接到末帧」。

### Requirement: 课件以外场景（待定）

系统 SHALL 支持白板模式（无课件时直接当电子白板使用）与录课（录制屏幕 + 麦克风 + 笔迹）。
